## 前提と非達成事項
- 「GCP水準」は証明書や単一機能ではなく、適用要件の特定、リスク分析、適切な設計・運用、試験による実証、記録管理、継続的変更管理の総体。
- 2026-11-15時点の記録上の**正式UAT 67件: PASS 32 / FAIL 1 / BLOCKED 29 / NOT RUN 5**。オフラインPASSを正式UATに加算しない。
- PR #16, #17はmainに統合済みで、UI/文面の限定修正。**これらのCI成功はシステム全体のCSV完了を意味しない**。
- PR #15 (v2.2.10候補)はdraft・未統合。TEST用30日CRFのversion 2保存成功応答と、Google Sheetsの独立読取に差異が残る。確認まではPASSや完全保存と扱わない。
- 実際の患者データ、メール、認証情報、既存本番・TEST/隔離環境はこの文書作成で一切変更しない。

### 重要な区別
- この表で「観察」はソースにあるコードや保存済みの記録による初期確認。「未確認」は不適合が確定した意味ではない。
- R3はリスクに見合うバリデーションを求める。67項目の件数だけをクリア目標にしない。研究参加者の安全と解析の信頼性に影響する経路を先に閉じる。
- 製品候補の企業への紹介・共同開発相談と、GCP準拠を謳った実運用・正式提供は別のゲート。

## 実装順序とExit Criteria

### Gate A: 本番保全と基準線確定
- 本番アプリ/GAS/Sheetの正確なデプロイ参照と読み取り専用ハッシュ・設定一覧（秘密値は記録しない）
- 制限された権限でバックアップ・閲覧権限・復旧手順の確認
- 優先リスクをCTQ（参加者安全・データ完全性・主要評価項目・登録判断）にマッピング
- 出力: Baseline Inventory / Risk Assessment / URS初版

### Gate B: 技術的P0を隔離環境で閉じる
- 実ユーザー個人識別と施設・役割ACL、監査イベント、CRF+監査原子性/回復、送信結果照合
- 改変・競合・二重送信・通信遮断・セッション失効等を完全架空データで注入
- 出力: 機能別仕様、単体・統合証拠、既知の差異/残存リスク
- **この段階で本番患者データへの試験書込は禁止**

### Gate C: 正式CSV/UAT
- 独立QAで試験計画・受入基準承認 → 実測 → 一次記録と追跡可能性照合 → CAPA → 最終レビュー
- 出力: RTM、UAT一覧（全必須PASSまたは正式なリスク受容）、Validation Summary Report、PI/QA release approval
- 新規の画面改善・改修後はリスクに応じた変更再検証

### Gate D: 継続運用と将来の企業向け提供
- SOP、ユーザー教育、委託先/環境管理、監視、インシデント対応、定期アクセスレビュー、定期バックアップ復旧試験
- プロトコルの変更は別途医学・倫理・規制承認を取ってから実装
- 製品デモは「開発・バリデーション中」と表示し、正式な適合性承認を示唆しない

## 最初の実務アクション
1. **現行のFAIL 1件の内容と修正証拠**を正式台帳から再同定する。
2. TEST版のversion2保存先不一致を独立照合で解く。既存UUIDの所在不明中は再送しない。
3. GCP-01/GCP-02/GCP-03の要求/リスク/試験ケースをRTM化し、隔離ブランチの既存実装と対応付ける。
4. GCP-04のValidation PlanとURS/FS、SOP素案を作り、QAレビューに備える。
5. 本番は現在のバージョンでの継続運用リスクを評価し、重大な不確定があれば適切なリスク軽減措置を講じる。
