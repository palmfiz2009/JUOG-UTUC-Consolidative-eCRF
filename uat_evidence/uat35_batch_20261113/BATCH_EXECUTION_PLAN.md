## 実施順と共通評価

1. 版/SHA・AUTH_CONNECT・業務台帳66行の基準を再確認。別の隔離fixture領域を予約し、fixtureハッシュとAPI allowlistを承認時に固定。既存970とその監査は保持する。
2. A群の正規役割認証・割当が成立したら中央判定/登録/上限を実行。B群はA群とは独立した登録済み971候補を使用できるが初期化は別途承認対象。
3. B群の正常保存と拒否を交互に行い、C群の復元・回帰、D群の臨床値保持へ同じ証拠を再利用。
4. 各操作のbefore/afterで旧CRF版/最新版/業務revision/業務監査/requestEventを比較。拒否でrequestEventが追加されても業務書込みと混同しない。
5. 実測は正規署名とGAS本人ACLを通す。operation_idを固定し、遅延時はstatus照会で確認してから同じIDで許可された回復だけを行う。新IDで再送しない。
6. 対象外更新、予期しない許可、秘密値露出があれば停止しAUTH_CONNECTへ戻す。既存業務履歴を削除して復元しない。

## fixture と権限の具体的境界

- A群：TEST01内の新規架空スクリーニングfixture A-SCR01〜08、上限用A-CN1/A-TOTAL/A-SDの分離スナップショット。名称は未予約。実JUOG番号はサーバー返却値を記録し推測で固定しない。19/41/11件の初期状態を設定するバッチは一覧・hash・件数を固定してから1回実行。
- B群：JUOG-971は既存の手術例候補、未作成/未allowlist。登録2026-04-01、手術2026-04-13、30日2026-05-13、31日2026-05-14、90日2026-07-12、6月2026-10-13。正当性は原仕様に照合し、初期化監査には実際の操作時刻を記録する。
- A群のfacility/radiology/medical_oncology/urology/adminは役割名であり、本人登録の承認ではない。PIが実担当者を指定し、正規OIDCで照合した者だけを割り当てる。全施設権限、本人ロールの無断変更、架空subject登録は禁止。
- B群は現在のfacility本人を再利用。既存970の新規保存は不要。C群の復元先ID/権限は未指定なので復元を実行しない。

## 読取・書込APIの限定候補

- A facility：submit_screening / get_screening_draft。MDT：list_review_cases / get_screening_crf / get_own_review / submit_mdt_review / get_mdt_reviews。admin：list_screenings / get_screening / finalize_mdt / stats / void_registration。分類訂正は既存ルート/SOPに対応するか未確定であり、未知APIを許可しない。
- B/D：save_draft / get_draft / get_crf_linkage / save_crf / read_crf。実際のprepare/execute/status封筒は承認済みoperation manifestへ束縛する。削除APIは含めない。
- C：隔離バックアップ取得・新規別領域復元・ローカル画像検査。外部Dropbox/メール/画像アップロードAPIは含めない。

現在のv5限定ガードは970と限られたAUTH-04操作に束縛されている。A/Bを単にフラグ変更で通さない。拡張ガード候補・ソースSHA・fixture一覧・役割割当のレビューが完了するまで、この計画の承認だけで送信可能にはならない。
