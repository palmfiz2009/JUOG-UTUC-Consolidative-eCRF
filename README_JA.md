# JUOG UTUC_Consolidative eCRF v2.2.2

研究計画書 第3版（2026/09/14）を基準にした本番前完成候補です。

## ワークフロー
1. 各施設が本人同意取得後、「中央MDT審査申請」を送信。
2. `JUOG-SCR-001` 形式のMDT受付番号を発行。これは正式登録番号ではない。
3. 放射線診断・腫瘍内科・泌尿器科の3領域が「中央MDT判定者専用」ページから独立判定を入力。
4. 3名が揃うまで事務局は正式登録できない。
5. 3名の結果を中央MDTで合意形成し、事務局が最終判定を確認。
6. 適格例のみ `JUOG-001` 形式の正式登録番号を発行。
7. 不適格例は正式登録せず、Screening/MDT記録のみ保持。登録42例には含めない。
8. 保留例は施設から追加情報を再提出すると同じ受付番号で新しい審査ラウンドを開始。
9. 正式登録後の30日・90日・6〜24か月CRFはGoogle Sheetへ自動保存する。

## Google Sheet タブ
- `Screening`: MDT申請ワークフローの現在状態
- `ScreeningCRF`: スクリーニングCRFの提出スナップショット（履歴保持）
- `ScreeningAudit`: 申請・再申請・最終MDT・正式登録の監査記録
- `MDTReviews`: 3名の個別判定。訂正も新versionとして追記
- `Registry`: 正式登録例のみ。施設RECIST・中央RECIST・一致/不一致を保持
- `CRF_30d`: 周術期・術後30日CRF。訂正は追記
- `CRF_90d`: 術後90日CRF。訂正は追記
- `CRF_Followup`: 6〜24か月定期経過CRF。訂正は追記
- `CRFSubmissionAudit`: 正式登録後CRFの提出監査記録
- `Settings`: 42例/cN1/SD等の登録制御

各CRFタブは解析しやすいようデータを列展開し、同時に `payload_json` に提出時の完全スナップショットを保持します。

## RECISTの扱い
- 施設RECISTと中央放射線診断医RECISTを別々に保持します。
- 両者が異なる場合も、中央RECISTがCR/PR/SDで中央MDTが合意すれば正式登録可能です。
- 適格性確認時の正式RECISTは中央判定です。
- `recist_concordance` に `CONCORDANT` / `DISCORDANT` を保存し、論文化時に一致率・不一致内容を記述できます。
- **SD 12例の登録管理は中央RECISTではなく、現行計画書に沿ってEVP最良総合効果（best_effect）を使用します。** 中央MDT提供画像が原則EVP導入前＋直近であり、best overall response全体を中央再判定する設計ではないためです。

## MDT判定
- 放射線診断：中央RECIST、他臓器浸潤、大血管浸潤、cM1活動性病変
- 腫瘍内科：Grade 3以上AE回復、ECOG PS、内科的手術移行安全性
- 泌尿器科：技術的切除可能性、Consolidative surgeryの外科的妥当性

各判定者は自分の判定提出前に他者の結果を見ません。最終判定は多数決で自動決定せず、中央MDT構成委員の合意を事務局が確認して確定します。

## データ保護
氏名、カルテ番号、住所等は入力しません。中央保存する生年月情報は年月のみで、日は保存しません。施設内研究対象者識別コードと個人の対応表は各施設で管理します。

## 検査項目のv3整合
尿一般検査（蛋白、糖、潜血、ウロビリノーゲン）はCRFから削除。尿細胞診は保持。血糖はスクリーニング時のみ収集。HbA1cは収集しません。

## 重要
MDT判定者への本番自動メール送信先は意図的に未設定です。UAT中に実在の判定者へダミー症例が送信されることを防ぐためです。本番直前に通知先を追加します。


## v2.2.2 入力エラー防止
- 身長 80–250 cm、体重 20–300 kg未満のみ許容（200 kgは許容、300 kgは拒否）。
- 血圧・脈拍・体温は、桁違いを防ぐため広い生理的範囲でhard stop。拡張期血圧が収縮期血圧以上の場合は送信不可。
- Hb 5 g/dLなど「異常だが実在しうる検査値」はrangeだけで拒否しない。
- 手術日<同意日、EVP最終投与日>手術日、評価日<手術日/予定日、死亡日<研究登録日はhard stop。
- 同じ重要日付矛盾はApps Script側でも再検証し、画面側を迂回してもGoogle Sheetへ保存しない。
